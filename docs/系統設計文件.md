## 1. 設計目標

1. **自帶 API**：使用者自行輸入 Base URL / API Key / 模型，連線任意 OpenAI 相容服務。
2. **對話為主**：多對話管理、串流回覆、上下文裁剪與 Markdown 呈現。
3. **多供應商相容**：不因特定供應商（如 DeepSeek 思考欄位）而破壞一般相容性；不支援的欄位在使用者明確設定時才送出。
4. **可診斷**：內建除錯記錄，無需 Logcat 即可排查連線問題。
5. **裝置適配**：手機與平板皆有一致且順暢的操作體驗。

---

## 2. 設計原則與取捨

| 決策 | 選擇 | 理由 |
| --- | --- | --- |
| 模組切分 | 單一 `app` module | 專案規模適中，避免多 module 的建置與維護成本。 |
| 架構 | MVVM + Repository | 與 Jetpack 生態一致，測試與維護性佳。 |
| 狀態來源 | 單一 `StateFlow` UI State | 易於推理，避免多來源狀態不一致。 |
| 對話建立時機 | **延後建立**（延遲至首則訊息） | 避免使用者誤觸產生空白對話。 |
| Token 估算 | 零依賴啟發式 | 只需近似即可裁剪，省去引入 tokenizer 的體積與複雜度。 |
| Markdown 渲染 | 自製零相依渲染器 | 精準控制表格、程式碼區塊與字型縮放，避免第三方相依膨脹。 |
| 歷史裁剪 | 僅裁剪送出子集 | 本機保留完整歷史，兼顧上下文成本與資料完整性。 |
| 串流 UI 更新 | 節流 50ms | 平衡即時感與 Compose 重組成本。 |

## 3. 應用程式外觀（App Shell）

`MainActivity` 為唯一 Activity，負責：

1. 以 `enableEdgeToEdge()` 啟用全螢幕邊到邊顯示。
2. 讀取 `AppSettingsViewModel` 的顯示模式 / 字型 / 朗讀語言設定。
3. 依 `screenWidthDp >= 600` 決定導航樣式：
   - **精簡**：底部 `NavigationBar`（僅頂層頁面顯示）。
   - **展開**：左側 `NavigationRail`。
4. 以 `CompositionLocalProvider` 提供 `LocalChatFontSize` 與 `LocalTtsLocale` 給子樹。

## 4. 導航與路由設計

路由集中於 `ui/navigation/Routes`：

| 路由 | 說明 | 參數 |
| --- | --- | --- |
| `CONVERSATIONS` | 對話清單（起始頁） | — |
| `PROFILES` | API 設定檔清單 | — |
| `PROFILE_EDIT` | 設定檔編輯 | `profileId: Long` |
| `CHAT` | 聊天頁 | `conversationId: Long`、`title: String?`（可選，標題預覽） |
| `DEBUG` | 除錯記錄 | — |
| `SETTINGS` | App 設定 | — |

**轉場設計**：

- `NavHost` 全域轉場為 `None`（關閉其他頁面切換動畫）。
- 僅 `chat` 路由覆寫：進入由右側滑入 + 淡入（160ms）、返回滑出 + 淡出（150ms）。
- 平板雙欄直接在清單選取，**不經路由、無轉場**。

**標題預覽**：由清單進入對話時，可透過 `CHAT` 路由的可選 `title` 參數帶入已知標題，讓標題列在**第一幀**即顯示正確名稱，避免先閃出「新對話」再切換（新對話仍顯示「新對話」）。

**頂層導覽切換**：`navigateToTopLevel` 使用 `popUpTo(startDestination) { saveState }` + `launchSingleTop` + `restoreState`，保留各分頁狀態。

## 5. 畫面設計

### 5.1 對話清單（`ConversationListScreen`）

- 顯示對話依「最後更新時間」新到舊排序。
- 標題「對話」右側以小字顯示**目前全域啟用的設定檔名稱**（隨設定頁切換即時更新）。
- 右上角齒輪進入 App 設定；右下角 ＋ 新增對話。
- 長按 / 圖示可重新命名、刪除（含確認）。
- 平板模式為清單 + 聊天**雙欄**。

### 5.2 聊天（`ChatScreen`）

- 標題列顯示當前對話標題。
- 訊息氣泡：使用者靠右、助理靠左；助理回覆以 Markdown 呈現。
- 氣泡下方顯示時間戳（當日 `HH:mm`，非當日 `MM-dd HH:mm`）。
- **Token 資訊列**：顯示本次估算 token 數與被省略的早期訊息數。
- **錯誤列**：顯示 HTTP 錯誤與伺服器回傳內容。
- 輸入區：送出鈕（串流中為停止鈕）；支援鍵盤 Enter / Send。
- 「回到底部」浮動按鈕。
- 朗讀時頂部列顯示播放 / 暫停 / 停止控制。

### 5.3 API 設定檔（`ProfileListScreen` / `ProfileEditScreen`）

- 清單：新增 / 編輯 / 刪除、RadioButton 選擇使用中設定檔。
- 編輯：欄位見 [`使用指南.md`](使用指南.md#3-首次設定建立-api-設定檔)。
- 測試連線成功後以**下拉選單**挑選模型，避免手打錯誤。

### 5.4 App 設定（`AppSettingsScreen`）

- 顯示模式、字型大小（附即時預覽）、總是朗讀、朗讀語言。

### 5.5 除錯記錄（`DebugLogScreen`）

- 由新到舊顯示、顏色分級、複製全部、清空、啟用開關。

## 6. 狀態管理

### 6.1 ChatUiState

```kotlin
@Immutable
data class ChatUiState(
    val conversation: Conversation? = null,
    val messages: List<Message> = emptyList(),
    val streamingText: String = "",
    val reasoningText: String = "",
    val isStreaming: Boolean = false,
    val error: String? = null,
    val omittedCount: Int = 0,
    val estimatedTokens: Int = 0,
    val inputText: String = "",
    val isLoadingMessages: Boolean = true
)
```

- 以 `MutableStateFlow` 持有，對外暴露唯讀 `StateFlow`。
- 串流文字與資料庫訊息分離：串流期間使用 `streamingText` / `reasoningText` 暫存，完成後才寫入 Room，避免半成品入庫。
- 自動朗讀以 `SharedFlow<AutoReadEvent>` 事件流傳遞，避免與 UI State 糾纏。

### 6.2 並行控制

- `sendJob`：新的送出會先取消舊的請求，避免卡住的舊連線阻塞新請求。
- `messagesJob`：切換對話時取消舊的訊息訂閱。
- 完成寫入於 `NonCancellable` 區塊：即使使用者按下停止，已產生的內容仍會保存。

## 7. 關鍵流程時序

### 7.1 送出與串流

```
User → ChatScreen → ChatViewModel.send()
     → Repository.getCurrentProfile()
     → (draft?) createConversation + observeMessages
     → getMessages → ContextBuilder.build()
     → addMessage(USER)
     → ChatRepository.stream() → ChatStreamClient (SSE)
          events: Delta / Reasoning / Completed / Failed
     → finally: addMessage(ASSISTANT) [NonCancellable]
                maybe AutoReadEvent
                reset streaming state
```

### 7.2 測試連線

```
User → ProfileEditScreen → ProfileViewModel.testConnection()
     → ProfileRepository.listModels(baseUrl, apiKey)
     → 成功：顯示模型下拉選單
     → 失敗：顯示 401/403/404/429/伺服器錯誤
```

### 7.3 進入既有對話

```
User → 對話清單 → navigate(chat/{id}?title=...)   # 帶入已知標題，第一幀即正確
     → ChatPane → ChatViewModel.init(id)
          ├─ 一次載入：getConversation(id) + getMessages(id) → 同時更新標題與訊息
          └─ startObservingMessages(id) → Room Flow 接手後續即時更新
     → 初始定位至最後一個問題
```

- TTS 引擎不在此流程建立，僅於使用者實際朗讀時初始化（見 [5.2](#52-聊天chatscreen)）。

## 8. 錯誤處理與邊界情況

| 情境 | 處理 |
| --- | --- |
| 未設定 API 即新增對話 | 引導至設定頁；送出時若無 Profile 顯示錯誤。 |
| Base URL / 模型為空 | 送出前驗證並顯示「缺少 Base URL 或模型名稱」。 |
| 伺服器忽略 `stream=true` | 自動改用一次非串流請求（後備）。 |
| 暫時性網路錯誤 / 429 / 5xx | 指數退避最多重試 3 次。 |
| 串流中使用者停止 | 已產生內容仍保存；標記為取消。 |
| 最終無內容 | 依 `finish_reason` 顯示中文提示。 |
| SSE 分塊無法解析 | 記錄到除錯記錄（`unparsed event`）並略過。 |
| 思考型模型只回思考內容 | 提示提高 Max Output Tokens 或停用 Thinking 模式。 |

## 9. 主題與響應式設計

- **主題**：Material 3；`LlmChatTheme(darkTheme)` 依 `ThemeMode` 決定；系統列圖示配色隨主題切換。
- **字型縮放**：透過 `LocalChatFontSize` 使 Markdown 標題、程式碼區塊、表格、輸入框與 Token 列依比例縮放。
- **響應式寬度**：600dp 門檻切換導航樣式與雙欄版面。
- **過場同步**：進入聊天路由時，底部導覽列與清單頁 ＋ 鈕與聊天頁轉場同步淡出 / 收起（約 160ms）。

## 10. 非功能需求

| 面向 | 設計 |
| --- | --- |
| 效能 | 串流 UI 節流 50ms；TTS 引擎延後至首次朗讀才初始化；開啟既有對話一次載入對話與訊息；過場動畫 160 / 150ms；R8 壓縮縮小 APK。 |
| 安全 | API Key 加密儲存、不落盤明文、不停用備份。 |
| 可維護性 | 分層架構、功能套件、集中日誌 TAG。 |
| 相容性 | 可空 DTO、寬鬆 JSON 解析、DeepSeek 欄位選擇性送出。 |
| 可診斷性 | 內建除錯記錄頁與可開關記錄器。 |

## 11. 已知限制與後續規劃

**已知限制**

- 需要自行提供 API：App 不內建任何金鑰。
- 允許明文 HTTP（為支援自架本機服務），請僅設定可信任端點。
- `thinking` / `reasoning_effort` 為 DeepSeek 特有；第三方轉接服務可能回 400。
- 逐字顯示取決於伺服器串流；端點若一次回傳整段則一次顯示。
- Token 估算為近似值，非精準計費依據。

**後續規劃（構想）**

- 對話匯出 / 匯入（JSON / Markdown）。
- 多模態附件（圖片）支援。
- 自訂系統提示範本庫。
- 語音輸入（STT）。
