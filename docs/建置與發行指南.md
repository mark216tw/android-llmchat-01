# 建置與發行指南（Build & Release Guide）

本文件說明如何由原始碼建置 **LLM Chat**、產生測試發行 APK，以及本專案的版本命名慣例。

---

## 1. 環境需求

| 項目 | 版本 |
| --- | --- |
| JDK | 17 或以上（本專案以 Java 17 為 target） |
| Android SDK | platform 35、build-tools 35 |
| Gradle | 8.9（隨附 wrapper，無需另行安裝） |
| AGP | 8.7.3 |
| Kotlin | 2.0.21 |
| 網路 | 首次建置需下載相依套件 |

於專案根目錄設定 `local.properties`：

```properties
sdk.dir=C\:\\Users\\<user>\\AppData\\Local\\Android\\Sdk
```

---

## 2. 常用建置指令

所有指令於專案根目錄執行（Windows PowerShell）：

```powershell
# 一般除錯版
.\gradlew.bat assembleDebug

# 測試發行版（R8 壓縮 + Debug 金鑰簽署）
.\gradlew.bat assemblePrerelease

# 發行版（未壓縮、無簽署設定）
.\gradlew.bat assembleRelease

# 清理
.\gradlew.bat clean
```

輸出位置：

| Build Type | 產物 |
| --- | --- |
| debug | `app\build\outputs\apk\debug\app-debug.apk` |
| prerelease | `app\build\outputs\apk\prerelease\app-prerelease.apk` |
| release | `app\build\outputs\apk\release\app-release-unsigned.apk` |

---

## 3. 測試發行版（prerelease）

`prerelease` 為本專案的**測試發行版本**，設定於 `app/build.gradle.kts`：

- **啟用 R8**：`isMinifyEnabled = true`（程式碼壓縮 / 混淆）。
- **資源壓縮**：`isShrinkResources = true`。
- **簽署**：使用系統自動產生的 **Debug 金鑰**（`signingConfigs.getByName("debug")`）。
- **版本**：`versionName = "1.0.0-prerelease"`。
- **產物**：`app-prerelease.apk`。

R8 規則集中於 `app/proguard-rules.pro`，涵蓋 kotlinx.serialization、Retrofit、OkHttp、Room、Hilt，並抑制 Tink / Error Prone 缺失類別警告。

> ⚠️ 此版本以 Debug 金鑰簽署，**不適合作為正式上線版本**，僅供測試與內部驗證。

---

## 4. 驗證產物

```powershell
# 檢視版本資訊
& "$env:ANDROID_HOME\build-tools\35.0.0\aapt.exe" dump badging `
    "app\build\outputs\apk\prerelease\app-prerelease.apk"

# 驗證簽章
& "$env:ANDROID_HOME\build-tools\35.0.0\apksigner.bat" verify --print-certs `
    "app\build\outputs\apk\prerelease\app-prerelease.apk"
```

預期結果：

- `versionName='1.0.0-prerelease'`
- 簽章 DN：`C=US, O=Android, CN=Android Debug`

---

## 5. 發行流程（GitHub Release）

1. 建置 `app-prerelease.apk`（見上）。
2. 於 GitHub 建立 Release，Tag 例如 `v1.0.0-prerelease`。
3. 勾選 **Set as a pre-release**（標記為 Pre-release）。
4. 上傳 `app-prerelease.apk` 作為附件。
5. 於 Release 說明標註「Pre-release 版本」與已知限制。

---

## 6. 版本命名慣例

本專案採用語意化版本（Semantic Versioning）精神：

```
<主版本>.<次版本>.<修訂版本>[-後綴]
```

- 正式：`1.0.0`
- 測試發行：`1.0.0-prerelease`

`versionCode` 為整數，隨發行遞增；`prerelease` build type 透過 `versionNameSuffix` 附加 `-prerelease`。
